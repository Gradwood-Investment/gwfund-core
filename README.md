# gwfund-core · 渐木公募基金研究系统 · 核心算法库

> **版本**：0.1.0 ｜ **许可**：Apache-2.0 ｜ **Python**：≥3.10
> **规范依据**：《附件A 算法引擎计算规范》v1.0 ｜《SOW v1.1》

四端（桌面 / 网站 / 小程序 / API）的**唯一算法真相源**。
任何端不得复制本包内的公式——这是四端一致性的地基（附件C MC-01）。

---

## 1. 它算什么

把「基金净值涨了多少」翻译成「基民到底赚了还是亏了、钱被谁赚走了」：

| 问题 | 本包给出的东西 | 对应模块 |
|---|---|---|
| 这只基金/公司实际收走了多少管理费（金额，不是费率） | `fees` | 式(3.1)–(3.8) |
| 同期基民作为一个整体是真赚还是真亏 | `identities.p_inv` | 式(4.1) |
| 基金涨了 20%、基民只赚 0.5%——差在哪 | `returns.investor_gap` | 式(5.1)–(5.3) |
| 规模从 26 亿变 39 亿，多少是客户申购、多少是市场涨跌 | `attribution.waterfall` | 式(6.1) |
| 日频份额没有，AUM 怎么估、误差多大 | `mixing` | 式(8.1)–(8.7) |
| 多少资金是在高位冲进来的、后来亏了多少 | `chase` | 式(9.1)–(9.5) |

**它不做什么**：不推荐基金、不预测涨跌、不给买卖点、不做交易。

## 2. 三条恒等式（全系统结论的基石）

```
A（规模恒等式）:  ΔAUM = R_net + NetSub − Div_cash + Other
B（盈亏恒等式）:  P_inv = ΔAUM + Div_cash − NetSub      （代入 A ⇒ P_inv = R_net + Other）
C（分配恒等式）:  R_gross = P_inv + Fee − Other          （Other = 0 时即 R_gross = P_inv + Fee）
```

> 基金像一个箱子。市场往箱子里放钱（毛收益），基金公司从箱子里拿走管理费（费用），
> 剩下的留给基民（净收益）。基民进进出出（申购赎回），但**进出本身不创造收益**。
> 所以：**基民赚的 + 基金公司收的 = 市场给的**。任何对不上的部分，都是数据或口径出了问题。

三条式的**地位必须区分**，否则引擎会自证正确：

| 式 | 地位 | 用途 |
|---|---|---|
| **(A)** | 定义式（`Other` 为残差） | 计算 `Other` |
| **(B)** | 独立构造式（`P_inv` 由市值/现金流构造） | 交叉校验 |
| **(C)** | 利润表校验式（`R_gross`/`Fee` 取年报） | 年度对账 |

## 3. 安装与运行（30 分钟内跑通）

```bash
# 方式一：开发模式（推荐，无需网络）
git clone <repo> && cd gwfund-core
python -m pytest            # 128 项测试，应全绿

# 方式二：安装为包
python -m pip install -e ".[dev]"
python -m pytest --cov=gwfund_core --cov-report=term
```

## 4. 快速上手

```python
from gwfund_core import returns, fees, identities, attribution
from datetime import date

# ── 1. TWR：日频 r_t 链式连乘 ──────────────────────────────
navs = [1.000, 1.100, 1.045, 1.0450]
rs = [returns.daily_return(navs[i-1], navs[i]) for i in range(1, len(navs))]
twr = returns.chain_return(rs)                       # +4.50%

# ── 2. MWR：现金流求 IRR（投资为负、收回为正）────────────────
res = returns.irr([-1_000_000, -500_000, 0, 1_520_000])
mwr = res.value                                      # +0.4978%

# ── 3. 基民收益缺口 = TWR − MWR ───────────────────────────
gap = returns.investor_gap(twr, mwr)                 # +4.0022 pct

# ── 4. 管理费逐日计提（注意：分母是 A_{t-1}，闰年 366）──────
acc = fees.daily_accrual(
    a_prev=10_000_000_000, on=date(2026, 6, 1),
    rate_mgmt_pct="1.20", rate_custody_pct="0.20",
)
acc.total                                            # 383561.64 元

# ── 5. 规模归因瀑布 ───────────────────────────────────────
rn = attribution.r_net_from_identity(a_start, a_end, net_sub, div_cash)
wf = attribution.waterfall(a_start, net_sub, rn, div_cash, a_end)
assert wf.passed                                     # 残差 < 0.5%
```

## 5. 缺失值纪律（最容易踩的一条）

| 情形 | 正确做法 | 禁止 |
|---|---|---|
| 基金成立前 / 清盘后 | 返回 `None` | 写 `0`、前向填充 |
| 百分比分母为 0 | 返回 `None` | 返回 `0` |
| 份额未披露 | 返回 `None` | 用前一期份额顶替 |
| 归一化残差超阈值 | **抛异常** | 静默返回 |

「缺失 = 不可得，不是 0，也不是沿用前值」（附件A §2.2）。

## 6. 精度策略

| 对象 | 类型 | 理由 |
|---|---|---|
| 金额（元） | `Decimal` | 禁止用 float 累加金额（SOW §5.8） |
| 费率（百分数） | `Decimal` | `"1.20"` 表示 1.20% |
| 收益率 / 比率 | `float` | IRR 需迭代求根，容差 1e-6 |
| 精度等级 | `PrecisionLevel` A/B/C/UNAVAILABLE | 必须随结果输出（附件A §6.4） |

## 9. 纪律

1. **口径先于指标**：任何数字必须能回答「用什么数据、什么区间、什么复权、什么分类」；
2. **可复核先于好看**：任何图表都能下钻到原始记录行；
3. **来源先于结论**：外部数据必须标注来源与获取时间；查不到写「未核实」；
4. **算法只有一份**：四端必须调用同一个 `gwfund-core` 版本。
